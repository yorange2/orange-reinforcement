# 简化版炉石传说

双人炉石，规则和原版一致。卡面**只有关键词**——没有战吼、亡语、光环等任何
需要额外结算的文本。留下的是炉石真正的骨架：费用曲线、随从交换、和每个关键词对场面
的影响。

```bash
.venv/bin/python -m hearthstone.play                # 跟 rule 打一局
.venv/bin/python -m hearthstone.play --watch        # 观战两个机器人互打
.venv/bin/python -m hearthstone.train               # 训练（默认 2000 局，约 12 秒）
.venv/bin/python -m hearthstone.bench --model hearthstone/models/agent.pt
.venv/bin/python -m unittest discover -s hearthstone/tests -t .
```

## 规则（和炉石一致）

| | |
| --- | --- |
| 英雄 | 30 点血，先打到 0 的一方获胜，同时归零算平局 |
| 法力 | 每回合上限 +1 并回满，上限 10 |
| 套牌 | 30 张，卡池中随机 15 张各两份，双方构成相同、只有洗牌顺序不同 |
| 起手 | 先手 3 张、后手 4 张 + 一张幸运币（双方在自己第一个回合再各抽一张） |
| 场地 | 最多 7 个随从；手牌上限 10 张，超出的牌抽出来就烧掉 |
| 随从 | 出场当回合不能攻击（召唤失调），之后每回合能攻击一次 |
| 攻击 | 可以打对面随从也可以打脸；伤害双向同时结算，血量 ≤ 0 就死 |
| 疲劳 | 牌堆抽空后每次抽牌吃 1、2、3… 点递增的疲劳伤害 |
| 幸运币 | 0 费法术，使用后本回合获得 1 点法力 |

砍掉的：起手调度（换牌）、职业和英雄技能。随从站位不影响任何东西——没有相邻效果，
出牌一律接在场上最右边。

## 先手优势

先手有优势是炉石的常态——Coin 是补偿，不是抹平。真实 HS 里先手胜率通常在 52~55%，
快攻 meta 更高。这个格式有冲锋、突袭、没有解牌，节奏更快：

| | 先手胜率 |
| --- | --- |
| random 镜像 | 52.2% |
| greedy 镜像 | 63.8% |
| rule 镜像 | 66.3% |

`random` 几乎不受影响（它连水晶都用不完），但两个会打的对手镜像时先手能拿六成以上。
这不是规则偏差——同一副牌先后手互换时，双方套牌构成相同、洗牌仅顺序不同，
纯粹是"先手先动"的优势在这套卡池里被放大了。

## 关键词

收录 10 个关键词，全部生效：

| 关键词 | 结算 |
| --- | --- |
| **冲锋** | 出场当回合就能攻击，随从和英雄都能打 |
| **突袭** | 出场当回合能攻击随从，但不能打脸（下回合起解除限制） |
| **嘲讽** | 对方必须先打它（潜行状态下不生效） |
| **潜行** | 不能被攻击指定为目标；自己发动攻击后失去潜行 |
| **圣盾** | 第一次受到伤害时完全免疫，然后圣盾消失 |
| **剧毒** | 被它造成伤害的随从直接死亡（伤害被圣盾完全挡下则不触发） |
| **风怒** | 每回合可以攻击两次 |
| **吸血** | 它造成多少伤害，自己的英雄就回多少血（不超过上限） |
| **复生** | 第一次死亡后带着 1 点血回到场上，且不再拥有复生 |
| **扰咒** | 不能被法术**指定**为目标——AoE、溅射和奥术飞弹的随机伤害照样打得到 |
| **法术增强** | 自己的法术**伤害** +1，可叠加；变形/消灭/乱斗/抽牌不受影响 |

## 三个手写的规则对手

| 名字 | 打法 |
| --- | --- |
| `random` | 合法动作里均匀随机，纯基准线 |
| `greedy` | 只会打脸的莽夫：随从全砸脸上，再用光水晶下随从 |
| `rule` | 先算斩杀 → 场面领先就施压、落后就挑最赚的交换 → 用满水晶 |

`rule` 一个回合内的顺序固定为**先攻击再出牌**——先攻击可以打死对面随从腾出场地。

每格 400 局，先后手轮换，随机基准 50%：

| 选手 | vs random | vs greedy | vs rule |
| --- | --- | --- | --- |
| `rule` | 99.8% | **60.5%** | 50.5% |
| `greedy` | 99.8% | 49.2% | 39.2% |
| `random` | 48.8% | 0.2% | 0.2% |

对角线全在 50% 附近，口径没偏。`random` 打 `greedy` 几乎赢不了，因为它连
"把水晶用完"都做不到。

## 强化学习

AlphaZero 风格二合一架构：共享局面编码器 + 策略头 + 价值头。
`(局面, 动作) -> 197 维特征`，局面只编码一次，策略头拼接动作特征打分，
价值头直接预测期望回报。PPO + GAE(λ=0.5) 训练。68k 参数（2×128 + LayerNorm）。

```bash
.venv/bin/python -m hearthstone.train                               # 默认 PPO 2000 局，约 13 秒
.venv/bin/python -m hearthstone.train --episodes 30000              # 正式训练再拉长（约 4 分钟）
.venv/bin/python -m hearthstone.train --gae-lambda 1.0              # 退回蒙特卡洛优势做对照
.venv/bin/python -m hearthstone.train --algo reinforce              # 切 REINFORCE 做对照
.venv/bin/python -m hearthstone.train --opponent mix --save hearthstone/models/agent.pt
```

### 层数：4 层的优势在 GAE 之后反转了

之前测过"2 层升到 4 层 +4.7pp"，但那是在 λ=1（蒙特卡洛优势）下测的。换成
GAE(λ=0.5) 重测（1 万局，3 seed）：

| | vs rule | vs greedy |
| --- | --- | --- |
| **2 层（68k）** | **65.70% ±0.62** | **74.60% ±0.80** |
| 4 层（101k） | 56.30% ±2.48 | 68.60% ±2.02 |

4 层现在**反而差 9.4pp**，而且 seed 之间的方差大了 4 倍（±2.48 vs ±0.62）。降完方差
之后，多出来的容量只是更容易把噪声拟合进去。所以默认和发布的权重都用 2 层。

### GAE：最优 λ 是 0.5，不是惯例的 0.95

最初的优势估计是"终局奖励按 `γ^(T−t)` 往回衰减，再减去价值头"——这其实正是
GAE 里 `λ=1` 的那个端点，也就是**方差最大**的一端。一局有 60 个决策点，第 3 回合
那一步的好坏被后面 50 多步的运气淹没。

换成 GAE(λ) 之后扫了一遍（6 seed × 2000 局训练 × 1000 局评测）：

| λ | vs rule | vs greedy |
| --- | --- | --- |
| 1.0（原来的实现） | 52.38% ±0.60 | 63.63% ±0.78 |
| 0.95 | 53.47% ±1.18 | 65.38% ±1.37 |
| 0.9 | 55.60% ±0.80 | 66.72% ±0.85 |
| 0.7 | 57.52% ±0.67 | 67.67% ±0.55 |
| **0.5** | **58.82% ±0.72** | **68.93% ±0.61** |
| 0.3 | 56.23% ±1.00 | 68.85% ±0.99 |
| 0.0 | 56.72% ±0.70 | 67.20% ±0.95 |

**λ=0.5 相对 λ=1 是 +6.43pp（t=6.9）**，训练时间不变。曲线是标准的倒 U，两个对手上
峰值位置一致。

为什么这么低？`γλ = 0.495` 意味着有效视界只有约 2 步，而平均每回合 3.4 个决策点——
等于**把信用分配压缩到大约一个回合以内**。这和炉石的结构吻合：一个动作的价值主要是
它对当前场面的即时影响，更远的交给价值头。这个 0.5 是被本环境的特性推下去的
（终局奖励、每局 60 个决策点），**别直接搬到别的项目**。

> 顺带一个教训：这个环境的训练是混沌的。固定 seed 只在优势上加一个比 float32 eps
> 还小的扰动，最终胜率就会漂 1~3pp。**任何小于约 2pp 的效应都必须多 seed 才能判断**，
> 重构后也不要指望结果逐位复现——GAE 的 λ=1 等价性是在数值层面验的
> （`tests/test_policy.py::TestGAE`），不是靠比训练结果。

### 试过但没用：先知价值头

价值头不参与线上决策（推理时根本不算），所以可以安全地给它作弊——这就是非对称
actor-critic，也是 Suphx 里 oracle guiding 的简化版。`--oracle` 会把对手的真实手牌
编码成 30 维喂给价值头。

实测**完全没有效果**：胜率 vs rule +0.25pp（t=0.24），而且价值头的解释方差从
+0.336 掉到 +0.309，连上游指标都没改善。原因是回报的残差方差（两边解释方差都只有
0.33）主要来自后续约 8 个回合、16 次抽牌的**将来**随机性，而先知特征描述的是对手
**当前**的手牌；加上双方牌堆镜像且构成已知，逐卡展开的边际信息量很小。

开关留着（默认关闭，有泄漏守卫测试），但别指望它。降方差的杠杆在回报构造上，
不在补充状态信息——这正是上面 GAE 那一节的由来。

### 特征实验：从 48 维升到 76 维

最初 48 维特征只描述了"这张牌是什么""这个随从是什么"，但没有告诉模型交易的结果。
比如"我这一刀能不能打死它""打完之后场面谁优"——这些信息网络可以从 48 维里自己推，
但那需要额外的隐藏层容量和更多的训练局数。直接把答案塞进特征里更便宜。

76 维新增了四块：

1. **交易结果**（谁死、过杀多少、交易后场面攻防差）
2. **手牌质量**（不只看有几张，还看能出什么——可出牌的总攻/总血、有没有冲锋/嘲讽）
3. **场上关键词分布**（双方各有多少剧毒/吸血/风怒/复生）
4. **斩杀检测**（自己和对手分别能不能在下次攻击中结束比赛）

| | 48 维 | 76 维 | 差 |
| --- | --- | --- | --- |
| vs greedy | 53.7% | **65.4%** | **+11.7pp** |
| vs rule | 43.5% | **56.0%** | **+12.5pp** |

全维度提升，训练速度几乎不变。这和跑得快那边的结论一致——**补信息
是比堆参数有效得多的方向**。网络规模 24x 换不来 2pp，多塞 28 维特征却能提 12pp。

### 特征 v5：从 76 维升到 197 维

76 维的局面特征是纯聚合统计量——ValueNet 看到的场面是"3 个随从，总攻击 10，总生命 15"，
分不清一个 8/8+两个 1/1 还是三个 3/3；手牌只知道"有冲锋"但不知道哪张。

v5（197 维）新增了三块局面特征：

1. **逐随从编码**（98 维）：双方场上 7 槽全覆盖（按出场顺序），每槽攻/血/能动/嘲讽/圣盾/剧毒/吸血
2. **逐手牌编码**（15 维）：可出牌中前 3 低费的费/攻/血/冲锋/突袭
3. **法术感知**（3 维）：手牌中是否有直伤/AOE/硬解法术

同时把先后手从"牌堆差推断"改为 Observation 的显式字段。

5 seed × 2000 局 PPO，每格 600 局评测：

| | 81 维 (旧) | 197 维 (新) | 差 |
| --- | --- | --- | --- |
| vs greedy | 62.6% ± 5.8 | **60.9%** ± 2.8 | −1.7pp |
| vs rule | 50.1% ± 6.8 | **50.2%** ± 1.8 | +0.1pp |

2000 局下 197 维学不充分，但**稳定性大幅提高**（方差从 ±6.8pp 降到 ±1.8pp）。
4 层 2 万局可进一步提升至 vs rule 54.7%（单次）。

### 特征（251 维）

前 60 维描述动作，后 191 维描述局面：

- 动作（60 维）：类型 one-hot、打出牌的费用/攻/血/11 个关键词、**卡面文本（18 维）**、
  攻击者的攻/血/剩余次数/圣盾/剧毒/吸血/风怒、目标（人脸/攻/血/嘲讽/圣盾/剧毒）、
  **交易结果（谁死/过杀/场面差）**、出牌后的水晶剩余、候选动作总数
- 局面（191 维）：水晶血量、武器、手牌质量 + 逐卡编码 + 法术感知、
  场面聚合 + **逐随从编码（7 槽 × 9 维）**、关键词计数、**场上文本感知（8 维）**、
  斩杀检测、牌堆/疲劳/先后手/bias

### 卡面文本特征（v6）

引擎加了战吼、亡语、光环、触发、条件之后，出现了一个隐蔽的问题：**这些卡在特征里
根本不存在**。水元素（4 费 3/6，冻结被它打到的角色）和一张同费同身材的白板随从，
编码出来**完全一样**——模型不可能学会"这张牌打出去会冻结对方"。

v6 补了三块：

1. **卡面文本（动作侧 18 维）**：先 5 个标签说"有没有战吼/亡语/光环/触发/条件"，
   再用量级说"有多大"（战吼的伤害/抽牌/召唤数、亡语的伤害/抽牌/召唤数、光环的攻血、
   法术的冻结/消灭）。标签向量的思路来自 RosettaStone 的 `game_tags`——一张卡由一组
   固定的属性标签刻画。**白板随从这一整块全是 0**，所以老卡的编码不受影响。
2. **逐随从槽位加 2 维**：亡语/触发。换掉一个带亡语的随从和换掉一个白板随从，
   代价完全不同。冻结不用单独加维——冻结的随从 `can_attack` 为假，"能动"那一维
   自动覆盖。
3. **场上文本感知（局面侧 8 维）**：双方各有多少带亡语/触发/光环的随从 + 冻结数量。

`FEATURE_DIM` 从 197 涨到 251，先知特征从 30 涨到 34（补了对手手牌里的文本分布）。

### 动作空间

`Action` 三种：

```python
Action("play",   source=手牌下标)             # 出随从或用法术（幸运币）
Action("attack", source=自己场上下标, target=对方场上下标或 HERO)
Action("end")                                  # 结束回合
```

和跑得快最关键的不同——一个回合是一串动作（出牌和攻击都不交出行动权），
信用分配要按整串来处理。其他一样：同名手牌去重，`obs` 里没有暗信息，
`arena.final_reward`（赢 +1 / 平 0 / 输了按对手剩血给 0~−1）和 `arena.duel`
（每副牌正反各打一遍）都写好了。

## 整回合搜索

把"这一整个回合怎么打"当成一个决策，而不是逐个动作贪心。枚举从现在到结束回合的所有
动作序列，用价值头评估每条线打完之后的局面，挑最好的一条。

```bash
.venv/bin/python -m hearthstone.bench --model hearthstone/models/agent.pt --search
.venv/bin/python -m hearthstone.bench --model ... --search --beam 24   # 调宽度
```

4 seed × 600 局，同一份权重上对比：

| | vs rule | vs greedy | 速度 |
| --- | --- | --- | --- |
| 纯策略（逐动作 argmax） | 58.75% ±0.82 | 68.46% ±0.70 | 2.7 ms/局 |
| 搜索 beam=4 | 70.04% ±0.99 | 80.50% ±1.12 | 14.4 ms/局 |
| **搜索 beam=8** | **73.12% ±1.33** | **81.25% ±0.91** | 22.1 ms/局 |
| 搜索 beam=24 | 72.08% ±1.05 | 81.38% ±1.16 | 48.3 ms/局 |

**+14.4pp（t=9.2）**，是目前所有改动里效应最大的一个。beam 从 8 加到 24 没有再涨
（差异在噪声内）却要两倍时间，所以默认就是 8——中位回合本来就只有几百条序列，beam 只在双方满场
的后期回合才真的起截断作用。

### 为什么是回合而不是 MCTS

这个格式实测的分支因子只有 4.4（中位 3），每回合平均 3.4 个决策点，中位回合的完整
序列数只有几百条、穷举 10ms 以内。往更深搜会立刻撞上对手手牌未知和抽牌随机，回报
衰减极快；而 MCTS 还要额外解决不完全信息（determinization / IS-MCTS），复杂度高得多。
把一个回合当一步，既吃掉了搜索的大部分收益，又完全绕开了隐藏信息——**自己回合内的
推演不需要知道对手手里有什么**。

### 信息边界

搜索要克隆真实 `Game`，也就顺带拿到了对手手牌和双方牌序。守住边界靠两件事：

1. 克隆后**先把自己的牌堆洗一遍**——刀扇/奥术智慧/疾跑会在回合内抽牌，不洗就等于
   预知自己的牌序（`test_search.py::test_root_shuffles_own_deck` 守着）。
2. 叶子评估只用 `state_features`，不碰先知特征。

`Game.clone()` 只复制会变的部分（`CardDef` 是不可变的 NamedTuple 可以共享），实测
8µs，比 `copy.deepcopy` 快 24 倍。

### 踩过的坑

第一版跑出 **10% 胜率**（纯策略是 58%）。表现是"动作/回合 2.3 vs 3.6、攻击次数腰斩"，
但全程不抛任何异常。

一开始怀疑价值头把叶子上随从的 `attacks_left=0` 误读成劣势，写了归一化去修，没用。
于是做判别实验：**把叶子评估换成一个明确奖励吃随从的手写启发式**——结果同样崩到
1.7%，这就把价值头排除了，问题锁进搜索机制本身。

真凶是 `choose` 里"只有一个合法动作"的提前返回**没有消费掉计划**，导致上一回合没走完
的动作序列漏进下一回合：开局先打一个陈旧动作，紧接着弹出"结束回合"。修法是把计划
绑定到它被搜出来的那个半回合上，`test_search.py::TestPlanIsolation` 守着这条。

教训：**先做能一刀切开假设空间的判别实验，别急着修第一个看起来合理的猜想。**

## 可以继续做的事

- **在新卡池下重训**：扰咒和法术增强补上之后没有重训，搜索因此掉了 2.5pp。另外特征
  里还没有"我当前有多少法术增强"这一维，加了才能真正用好它（会改 `FEATURE_DIM`）。
- **把搜索结果回灌训练**：现在搜索只在推理时用，训练还是纯 PPO。用搜索选出的动作
  当策略目标（AlphaZero 那套）大概率还能再涨一截。
- **在目标预算下重扫 λ**：0.5 是在 2000 局上调的，样本变多后价值头会更准、蒙特卡洛
  方差相对下降，最优 λ 大概率往上漂。
- **加职业和英雄技能**：猎人射箭、法师火冲这类，成本最低的增加决策维度的方法。
- **加战吼/亡语**：哪怕只加一两张，决策空间也会大不少。
- **网页版**：放 `docs/hearthstone/`，再往 `docs/index.html` 加一个入口。
