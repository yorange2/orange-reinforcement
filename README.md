# orange-reinforcement

从零实现三人**跑得快**，再用强化学习训练一个策略网络，去打赢手写的规则算法。

牌型、引擎、规则对手、特征、训练、人机对战全都在这个仓库里，没有外部游戏环境依赖，
只需要 `torch` 和 `numpy`。

## 效果

每格 1500 局，轮转座位抵消 ♦3 的先手优势，同一批牌局横向可比。**三家游戏的随机基准是 33.3%**：

| 选手 | vs 2×random | vs 2×greedy | vs 2×rule |
| --- | --- | --- | --- |
| **模型（PPO，22k 参数，默认）** | 87.3% | 65.1% | **48.7%** |
| 模型（PPO，547k 参数） | **88.2%** | **73.4%** | **51.3%** |
| rule（最强的手写算法） | 78.4% | 64.9% | 34.9% |
| greedy | 65.3% | 34.7% | 13.7% |
| random | 32.1% | 12.0% | 7.0% |

关键是最后一列：模型夹在两个 `rule` 机器人中间能拿到 **48.7~51.3%**，而 `rule` 自己坐同一个
位置只有 34.9%（即基准线）。也就是说模型不只是"会打牌"，是确实**打赢了造它的那个启发式算法**。

对角线上同类打同类都落在 33% 附近（34.7% / 34.9% / 32.1%），说明评测口径没有系统性偏差。

训练过程（默认 PPO，12 万局，CPU 上约 4 分钟，约 520 局/秒）：

```
第  10000 局  近 10000 局胜率  39.4%
第  40000 局  近 10000 局胜率  43.8%
第  80000 局  近 10000 局胜率  46.5%
第 120000 局  近 10000 局胜率  46.7%
```

（训练时的胜率低于评测胜率，因为训练在按概率采样动作以保持探索，评测走贪心。）

## 对照实验：算法 × 模型大小

跑了完整的 2×2 对照——**REINFORCE / PPO** × **22k / 547k 参数**，四组的训练预算、超参、
随机种子、对手完全相同（都是 12 万局对 `rule`）。

### 对规则对手的胜率（每格 1500 局）

| 模型 | vs 2×random | vs 2×greedy | vs 2×rule | 训练速度 |
| --- | --- | --- | --- | --- |
| REINFORCE 22k | 87.4% | 74.3% | 51.3% | 470 局/秒 |
| REINFORCE 547k | 86.0% | 63.3% | 45.7% | 297 局/秒 |
| PPO 22k | 87.3% | 65.1% | 48.7% | 520 局/秒 |
| PPO 547k | 88.2% | 73.4% | **51.3%** | 159 局/秒 |

### 模型直接同桌（每副牌打满 6 种座位排列，每人基准 33.3%）

| 对局（各 1800 局） | 结果 | 差距 |
| --- | --- | --- |
| PPO 547k **vs** REINFORCE 547k | **40.4%** vs 34.9% | +5.5 |
| PPO 22k **vs** REINFORCE 22k | **39.2%** vs 37.5% | +1.7 |
| PPO 22k **vs** PPO 547k | **39.0%** vs 36.1% | +2.9 |
| PPO 547k **vs** REINFORCE 22k | **39.6%** vs 38.1% | +1.5 |

（每组的第三家都是 `rule`，它稳定被压在 22~25%。）

### 三个结论

**1. PPO 的样本效率碾压 REINFORCE。** 这是差距最大的一项：PPO 只用 **2000 局**就打到 49%（对 2×rule），
REINFORCE 要 **12 万局**才到 51%——大约 50 倍。原因就是 PPO 能把同一批数据安全地重复用 4 轮，
而 REINFORCE 用一次就扔。

**2. PPO 救回了大模型。** 之前那个"25 倍参数反而更弱"的结论，换算法之后不成立了：

```
            2万局   4万局   6万局   8万局   10万局  12万局
REINFORCE   39.9%  43.7%  44.9%  44.6%  40.5%  43.3%   <- 6 万局见顶后崩了
PPO         43.5%  45.5%  45.8%  45.8%  46.4%  46.4%   <- 一路稳住
```

大模型对 `rule` 从 45.7% 提到 51.3%，直接对打也以 40.4% 比 34.9% 赢下自己的 REINFORCE 版本。
裁剪把单次更新的幅度限制住了，参数多不再等于容易被噪声带偏——**之前的瓶颈确实是算法方差，不是容量**。

**3. 但"更大"依然没有变成"更强"。** 即使都用 PPO，22k 的小模型直接对打仍然小胜 547k 的大模型
（39.0% vs 36.1%），而且训练快 3 倍。现在的瓶颈换成了**输入**：40 维手工特征的信息量是固定的，
`estimate_turns` 之类的特征已经把牌力判断嚼碎喂进去了，再多的参数也没有新东西可挖。
下一步该动的是特征表示（原始牌面 + 编码器让网络自学），而不是继续堆参数。

> 注意小模型两种算法的差距（51.3% vs 48.7% 对 rule，直接对打 39.2% vs 37.5%）在 1~2 个标准差
> 之内，算打平；真正稳的结论是大模型那组的 +5.5。另外 PPO 22k 对 `greedy` 只有 65.1%，
> 明显是只对着 `rule` 训练练出的偏科——想要更均衡可以用 `--opponent mix`。

四份权重都在仓库里，可以自己复现：

```bash
.venv/bin/python bench.py --model models/ppo_small.pt --model models/ppo_big.pt \
    --model models/reinforce_small.pt --model models/reinforce_big.pt --games 1500
.venv/bin/python duel.py model:models/ppo_big.pt model:models/reinforce_big.pt rule --deals 300
```

## 游戏规则

采用常见的三人 16 张变体：

- **牌堆**：54 张去掉大小王和四个 2，剩 **48 张**，每人 16 张。
- **大小**：3 < 4 < … < 10 < J < Q < K < A。没有 2 和王，所以顺子不用处理回绕。
- **先手**：谁摸到 ♦3 谁先出，且**第一手必须包含 ♦3**。
- **跟牌**：同牌型、同长度、点数更大才能压；跟不起或不想跟就"过"；其余两家都过之后，
  最后出牌的人重新自由出牌。
- **牌型**：单张、对子、三张、三带一、三带二、顺子（≥5 张）、连对（≥2 对）、
  飞机（≥2 个连续三张，可带单或带对）、炸弹（四张同点，压任何非炸弹，炸弹之间比点数）。
- **胜负**：先出完手牌的人赢。

（`combos.py` 顶部写清了本项目采纳的每条细则，换变体改那里即可。）

## 强化学习是怎么做的

### 难点：动作空间是变长的

跑得快每一步的合法出牌数量都不一样——本项目实测**平均 40 个、最多 80 多个**，而且
同一个"动作"（比如"出一个对子"）在不同手牌下含义完全不同。用固定动作头的 DQN 会很别扭。

### 做法：逐动作打分，只在合法动作上归一化

```
score_i = f(特征(局面, 动作_i))     # 所有候选共享同一个打分网络
π(动作_i) = softmax(score)_i        # 只在当前合法的候选里归一化
```

这样合法动作有几个都无所谓，而且没见过的牌型组合也能靠特征泛化。默认网络是个 40→128→128→1
的 MLP（用 `--hidden` / `--layers` 可以任意加大）。

训练默认用 **PPO**（`--algo reinforce` 可以切回带基线的 REINFORCE 做对照）。两者共用同一套
优势估计：优势 = 折扣回报 − V(局面)，V 由一个小价值网络估计，优势做批内标准化，再加熵奖励维持探索。
差别只在策略损失和更新轮数：

```
REINFORCE:  L = -log π(a|s) · A                        一批数据只用一轮
PPO:        r = π_new(a|s) / π_old(a|s)
            L = -min( r·A , clip(r, 1-ε, 1+ε)·A )      同一批数据重复 4 轮，ε=0.2
```

裁剪把单次更新的幅度限制在 ±20% 以内，策略不会被一次大梯度推飞，所以同一批数据可以安全地
反复利用——这就是 PPO 样本效率高出一个数量级的原因。

实现上有个细节：为了能重复前向，采样时**不挂计算图**，只记录「特征矩阵 + 选了哪个动作 +
旧策略给的 log 概率」，更新时再用当前网络重新算。一批约 800 个决策点的动作数各不相同
（10~80 个），统一补齐成矩形、用 mask 在 softmax 前填 `-inf`，就能一次性前向完（`make_batch`
和 `evaluate_batch`）。副作用是 rollout 反而变快了。

### 回报设计

赢了 +1；输了按剩牌给 `-剩余张数/16`。比纯 ±1 学得快——输的时候剩 1 张和剩 12 张
显然不是一回事，这个稠密一点的信号让模型更快学会"先把手牌拆干净"。

### 特征（40 维）

前 26 维描述**候选动作**，后 14 维描述**局面**（同一决策点里对所有候选相同）：

- 动作：牌型 one-hot、点数、张数、连长、是不是炸弹、是不是"过"、**出完之后手牌还剩几轮能走完**、
  这一手把手里的对子/三张/炸弹拆散了几组、带牌张数、比这手大的牌在暗牌里占多少比例、出完是不是就赢了。
- 局面：自己剩几张、对手各剩几张、有没有人只剩 ≤2 张、当前要压什么、合法动作有几个、
  当前牌面是不是自己打的。

其中"**还剩几轮能走完**"（`estimate_turns`）是最关键的一个：贪心把手牌拆成顺子/连对/炸弹/
三带一等等，数需要几轮出完。它给了网络一个"这一手把牌拆坏了没有"的直接信号。这个函数按
点数签名做了 LRU 缓存，否则训练时每步要重算几十次。

## 三个手写的规则对手

它们既是训练对手，也是衡量模型强弱的标尺：

| 名字 | 打法 |
| --- | --- |
| `random` | 合法动作里均匀随机，纯基准线 |
| `greedy` | 能压就压，永远出最便宜的牌；不留大牌、不管对手还剩几张 |
| `rule` | 会算手牌拆解：优先出拆得最干净的一手、保留炸弹、不用 K/A 去压小牌、对手只剩 ≤2 张时改用大牌压制、能一把走完立刻走 |

`rule` 是个相当像样的对手——它打 `greedy` 有 64.9%，打 `random` 有 78.4%。

## 常用命令

```bash
# 训练：默认只跑 2000 局（约 8 秒），够快速验证一个想法
.venv/bin/python train.py
.venv/bin/python train.py --episodes 120000 --batch 32 --lr 7e-4   # 出正式结果再拉长
.venv/bin/python train.py --algo reinforce           # 切回 REINFORCE 做对照
.venv/bin/python train.py --hidden 512 --layers 3 --save models/big.pt   # 更大的模型
.venv/bin/python train.py --opponent mix          # 每局随机抽两个不同对手，更耐打
.venv/bin/python train.py --help

# 评测：对规则对手的胜率表，--model 可以给多个
.venv/bin/python bench.py --model models/ppo_small.pt --model models/ppo_big.pt --games 1500

# 让两个模型直接对打（每副牌打满 6 种座位排列）
.venv/bin/python duel.py model:models/ppo_big.pt model:models/reinforce_big.pt rule --deals 300
.venv/bin/python duel.py model:models/agent.pt rule greedy --deals 300

# 对战 / 观战
.venv/bin/python play.py --opponent rule          # 你 vs 2 个规则机器人
.venv/bin/python play.py --opponent model --model models/agent.pt
.venv/bin/python play.py --watch --model models/agent.pt   # 只看机器互打
```

## 测试

```bash
.venv/bin/python -m unittest discover -s tests -t .
```

105 个测试，约 2 秒。除了常规的牌型和引擎规则，有三个值得一提：

- **牌型往返一致性**：随机发几百手牌，枚举出的每一个合法动作都要能被 `classify()`
  反向识别成同样的牌型、点数和连长——生成器和识别器互相验证。
- **规则对手强弱梯度**：断言 `rule > greedy > random`，并且同类打同类必须落在 33.3% 附近。
  这条测试挂了，说明评测口径出了问题，模型胜率也就没有意义了。
- **变长动作集的掩码**：补齐用的填充位概率必须恒为 0，且批量打分要和逐个打分数值一致。
  掩码漏一点，梯度就全错，而且训练照样能跑完、只是学不出东西——这种 bug 最难发现。

## 可以继续做的事

- **换特征表示**：这是现在最该动的地方。PPO 已经把算法方差这个瓶颈解决了，但 40 维手工特征
  的信息量卡住了模型上限——大模型再大也挖不出新东西。改成原始牌面 + 编码器让网络自学特征，
  容量才可能真正兑现。
- **自我对弈**：目前只对规则对手训练，容易学成"专门克制这几个机器人"。自我对弈 + 对手池
  会更通用。
- **补全信息利用**：现在只用了公开信息，可以加对手手牌的概率推断。
- **换变体**：连对最少几对、飞机怎么带、要不要保留 2 和王，都在 `combos.py` 顶部集中定义。
