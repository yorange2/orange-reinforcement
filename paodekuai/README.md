# 跑得快

从零实现三人**跑得快**，再用强化学习训练一个策略网络，去打赢手写的规则算法。

### 👉 [在线试玩](https://yorange2.github.io/orange-reinforcement/paodekuai/)

打开就能跟模型对战，不用装任何东西。每步都能看到它对每手牌的打分。
（[实现细节](#在线试玩)）

牌型、引擎、规则对手、特征、训练、人机对战全都在这个仓库里，没有外部游戏环境依赖，
只需要 `torch` 和 `numpy`。

## 效果

每格 1500 局，轮转座位抵消 ♦3 的先手优势，同一批牌局横向可比。**三家游戏的随机基准是 33.3%**：

| 选手 | vs 2×random | vs 2×greedy | vs 2×rule |
| --- | --- | --- | --- |
| **模型（`paodekuai/models/agent.pt`，23k 参数）** | **91.3%** | **75.2%** | **53.7%** |
| rule（最强的手写算法） | 78.4% | 64.9% | 34.9% |
| greedy | 65.3% | 34.7% | 13.7% |
| random | 32.1% | 12.0% | 7.0% |

关键是最后一列：模型夹在两个 `rule` 机器人中间能拿到 **53.7%**，而 `rule` 自己坐同一个
位置只有 34.9%（即基准线）。也就是说模型不只是"会打牌"，是确实**打赢了造它的那个启发式算法**。

对角线上同类打同类都落在 33% 附近（34.7% / 34.9% / 32.1%），说明评测口径没有系统性偏差。

训练过程（默认 PPO，12 万局，CPU 上约 4 分钟，约 520 局/秒）：

```
第  40000 局  近 40000 局胜率  47.9%
第  80000 局  近 40000 局胜率  51.2%
第 120000 局  近 40000 局胜率  52.2%
```

（训练时的胜率低于评测胜率，因为训练在按概率采样动作以保持探索，评测走贪心。）

## 对照实验：算法 × 模型大小

跑了完整的 2×2 对照——**REINFORCE / PPO** × **22k / 547k 参数**，四组的训练预算、超参、
随机种子、对手完全相同（都是 12 万局对 `rule`）。

### 对规则对手的胜率（每格 1500 局）

| 模型 | vs 2×random | vs 2×greedy | vs 2×rule | 训练速度 |
| --- | --- | --- | --- | --- |
| REINFORCE 22k | 87.4% | 74.3% | 51.3% | 470 局/秒 |
| REINFORCE 547k | 86.0% | 63.3% | 45.7% | 297 局/秒 |
| PPO 22k | 87.3% | 65.1% | 48.7% | 520 局/秒 |
| PPO 547k | 88.2% | 73.4% | **51.3%** | 159 局/秒 |

### 模型直接同桌（每副牌打满 6 种座位排列，每人基准 33.3%）

| 对局（各 1800 局） | 结果 | 差距 |
| --- | --- | --- |
| PPO 547k **vs** REINFORCE 547k | **40.4%** vs 34.9% | +5.5 |
| PPO 22k **vs** REINFORCE 22k | **39.2%** vs 37.5% | +1.7 |
| PPO 22k **vs** PPO 547k | **39.0%** vs 36.1% | +2.9 |
| PPO 547k **vs** REINFORCE 22k | **39.6%** vs 38.1% | +1.5 |

（每组的第三家都是 `rule`，它稳定被压在 22~25%。）

### 三个结论

**1. PPO 的样本效率碾压 REINFORCE。** 这是差距最大的一项：PPO 只用 **2000 局**就打到 49%（对 2×rule），
REINFORCE 要 **12 万局**才到 51%——大约 50 倍。原因就是 PPO 能把同一批数据安全地重复用 4 轮，
而 REINFORCE 用一次就扔。

**2. PPO 救回了大模型。** 之前那个"25 倍参数反而更弱"的结论，换算法之后不成立了：

```
            2万局   4万局   6万局   8万局   10万局  12万局
REINFORCE   39.9%  43.7%  44.9%  44.6%  40.5%  43.3%   <- 6 万局见顶后崩了
PPO         43.5%  45.5%  45.8%  45.8%  46.4%  46.4%   <- 一路稳住
```

大模型对 `rule` 从 45.7% 提到 51.3%，直接对打也以 40.4% 比 34.9% 赢下自己的 REINFORCE 版本。
裁剪把单次更新的幅度限制住了，参数多不再等于容易被噪声带偏——**之前的瓶颈确实是算法方差，不是容量**。

**3. 但"更大"依然没有变成"更强"。** 即使都用 PPO，22k 的小模型直接对打仍然小胜 547k 的大模型
（39.0% vs 36.1%），而且训练快 3 倍。现在的瓶颈换成了**输入**：40 维手工特征的信息量是固定的，
`estimate_turns` 之类的特征已经把牌力判断嚼碎喂进去了，再多的参数也没有新东西可挖。
下一步该动的是特征表示（原始牌面 + 编码器让网络自学），而不是继续堆参数。

> 注意小模型两种算法的差距（51.3% vs 48.7% 对 rule，直接对打 39.2% vs 37.5%）在 1~2 个标准差
> 之内，算打平；真正稳的结论是大模型那组的 +5.5。另外 PPO 22k 对 `greedy` 只有 65.1%，
> 明显是只对着 `rule` 训练练出的偏科——想要更均衡可以用 `--opponent mix`。

> 上面这些是当时用 40 维特征跑出来的实测结果。那四份权重后来没有继续随仓库提供
> （加了特征之后维度对不上，留着也是历史包袱），要复现需要按下面的命令重训，
> 每组 4~13 分钟：
>
> ```bash
> .venv/bin/python -m paodekuai.train --episodes 120000 --batch 32 --lr 7e-4 --entropy-coef 0.005 \
>     --algo ppo --save paodekuai/models/ppo_small.pt                      # 换 --algo reinforce 得到对照组
> .venv/bin/python -m paodekuai.train --episodes 120000 --batch 32 --lr 7e-4 --entropy-coef 0.005 \
>     --algo ppo --hidden 512 --layers 3 --save paodekuai/models/ppo_big.pt
> ```
>
> 注意现在是 42 维特征，重训出来的绝对数值会比上表高一些（正式模型对 2×rule 已经到 52.4%），
> 但几组之间的相对关系应该是稳的。

## 特征实验：给模型"看见"带出去的是什么牌

原本 40 维特征描述一手牌时，只记了牌型、主牌点数、拆解代价，**没记带出去的那张牌本身**。
后果是模型在这种局面下只能瞎猜：

```
手牌: ♥6 ♦7 ♥7 ♦8 ♠8 ♣9 ♠9 ♥J ♦Q ♥Q ♠Q ♣K      要压: 三带一[♦6 ♦10 ♣10 ♥10]

QQQ 带 ♥6   分数 52.11   概率 33.3%
QQQ 带 ♥J   分数 52.11   概率 33.3%     <- 三个分数完全相同
QQQ 带 ♣K   分数 52.11   概率 33.3%
```

牌型、主牌、剩余轮数、拆不拆对子全都一样，在网络眼里这三手就是同一件事。但实战里差别很大：
应该甩掉没用的 6，而不是把 K 当废牌扔了。

补上两维 `attach_rank_max` / `attach_rank_min`（带牌的最大/最小点数）后，同一个局面：

```
QQQ 带 ♥6   分数  9.10   概率 99.5%     <- 甩废牌
QQQ 带 ♥J   分数  3.76   概率  0.5%
QQQ 带 ♣K   分数  1.58   概率  0.1%     <- 留大牌
```

排序完全正确，而且这只训练了 2000 局。

胜率上也是稳定的正向。8 个种子配对对比，每个种子两边同预算（2000 局）、同随机种子，
各打 1000 局评测：

| | 基线 40 维 | 加带牌点数 42 维 | 差 |
| --- | --- | --- | --- |
| 8 个种子平均（对 2×rule） | 41.5% | **42.9%** | **+1.45** |
| 正向的种子数 | — | — | 7 / 8 |

配对 t 检验 t=3.8、p<0.01，是个站得住的提升——虽然只有 1.5 个百分点，但方向明确，而且
说明"补信息"确实是比"堆参数"更有效的方向（25 倍参数量换来的是 −3 个百分点）。

仓库里的正式模型 `paodekuai/models/agent.pt` 就是用这套 42 维特征重训的，对 2×rule 从旧版的 48.7%
提到了 **52.4%**（再叠加下面的 LayerNorm 到 53.7%），`greedy` 那栏也从 65.1% 提到 72.4%。

## 游戏规则

采用常见的三人 16 张变体：

- **牌堆**：54 张去掉大小王和四个 2，剩 **48 张**，每人 16 张。
- **大小**：3 < 4 < … < 10 < J < Q < K < A。没有 2 和王，所以顺子不用处理回绕。
- **先手**：谁摸到 ♦3 谁先出，且**第一手必须包含 ♦3**。
- **跟牌**：同牌型、同长度、点数更大才能压；跟不起或不想跟就"过"；其余两家都过之后，
  最后出牌的人重新自由出牌。
- **牌型**：单张、对子、三张、三带一、三带二、顺子（≥5 张）、连对（≥2 对）、
  飞机（≥2 个连续三张，可带单或带对）、炸弹（四张同点，压任何非炸弹，炸弹之间比点数）。
- **胜负**：先出完手牌的人赢。

（`combos.py` 顶部写清了本项目采纳的每条细则，换变体改那里即可。）

## 强化学习是怎么做的

### 难点：动作空间是变长的

跑得快每一步的合法出牌数量都不一样——本项目实测**平均 40 个、最多 80 多个**，而且
同一个"动作"（比如"出一个对子"）在不同手牌下含义完全不同。用固定动作头的 DQN 会很别扭。

### 做法：逐动作打分，只在合法动作上归一化

```
score_i = f(特征(局面, 动作_i))     # 所有候选共享同一个打分网络
π(动作_i) = softmax(score)_i        # 只在当前合法的候选里归一化
```

这样合法动作有几个都无所谓，而且没见过的牌型组合也能靠特征泛化。默认网络是个 40→128→128→1
的 MLP（用 `--hidden` / `--layers` 可以任意加大）。

训练默认用 **PPO**（`--algo reinforce` 可以切回带基线的 REINFORCE 做对照）。两者共用同一套
优势估计：优势 = 折扣回报 − V(局面)，V 由一个小价值网络估计，优势做批内标准化，再加熵奖励维持探索。
差别只在策略损失和更新轮数：

```
REINFORCE:  L = -log π(a|s) · A                        一批数据只用一轮
PPO:        r = π_new(a|s) / π_old(a|s)
            L = -min( r·A , clip(r, 1-ε, 1+ε)·A )      同一批数据重复 4 轮，ε=0.2
```

裁剪把单次更新的幅度限制在 ±20% 以内，策略不会被一次大梯度推飞，所以同一批数据可以安全地
反复利用——这就是 PPO 样本效率高出一个数量级的原因。

实现上有个细节：为了能重复前向，采样时**不挂计算图**，只记录「特征矩阵 + 选了哪个动作 +
旧策略给的 log 概率」，更新时再用当前网络重新算。一批约 800 个决策点的动作数各不相同
（10~80 个），统一补齐成矩形、用 mask 在 softmax 前填 `-inf`，就能一次性前向完（`make_batch`
和 `evaluate_batch`）。副作用是 rollout 反而变快了。

### 归一化：用 LayerNorm，不能用 BatchNorm

`MoveScorer` 的输入是 `(候选动作数, 42)`——**这个"批"维度装的是待比较的选项，不是独立样本**。
BatchNorm 沿着它求统计量会带来两个硬伤：

1. **一手牌的分数会取决于当时碰巧还有哪些牌可出。** 而且训练时更糟：为了一次性前向，一批
   数据被补齐成矩形，里面混着大量补零的假行（一个决策点可能只有 10 个候选却被补到 80 行）。
   现在这些假行完全无害，因为网络是逐行独立作用的；用了 BatchNorm 它们就会污染真实候选的归一化。
2. **PPO 的概率比会失去意义。** `r = π_new(a|s) / π_old(a|s)` 成立的前提是 π 只是"状态 + 参数"
   的函数。BatchNorm 让 π 额外依赖同批次的其他样本，而采样时的批（一个决策点的 10~80 个候选）
   和更新时的批（800 个决策点 × 补齐宽度）完全不是一回事，算出来的比值不再是真正的新旧策略比。

LayerNorm 没有这些问题——它在单个样本的特征维度内归一化，候选之间互不影响，训练和推理行为一致。
有一条测试专门钉住这个性质：同一批一起算、逐个算、补假零行再算，三者结果必须完全相同。

实测（12 万局，其余配置完全相同）：

| | vs 2×random | vs 2×greedy | vs 2×rule | 直接对打 |
| --- | --- | --- | --- | --- |
| 无归一化 | 90.0% | 72.4% | 52.4% | 38.3% |
| **LayerNorm** | **91.3%** | **75.2%** | **53.7%** | **39.7%** |

三栏全赢，直接同桌 1800 局也赢，所以设成了默认（`--norm none` 可以关掉）。

需要说明的是，**单看任何一项都不算决定性**：2000 局预算下 8 种子配对是 +1.2pp、7/8 正向，
但配对 t 只有 1.30（p≈0.23）；正式预算下直接对打也只领先 1.4pp。是所有测量方向一致才采纳的，
不是某一项证据特别强。

### 回报设计

赢了 +1；输了按剩牌给 `-剩余张数/16`。比纯 ±1 学得快——输的时候剩 1 张和剩 12 张
显然不是一回事，这个稠密一点的信号让模型更快学会"先把手牌拆干净"。

### 特征（42 维）

前 28 维描述**候选动作**，后 14 维描述**局面**（同一决策点里对所有候选相同）：

- 动作：牌型 one-hot、点数、张数、连长、是不是炸弹、是不是"过"、**出完之后手牌还剩几轮能走完**、
  这一手把手里的对子/三张/炸弹拆散了几组、带牌张数、**带出去的牌本身是大是小**、
  比这手大的牌在暗牌里占多少比例、出完是不是就赢了。
- 局面：自己剩几张、对手各剩几张、有没有人只剩 ≤2 张、当前要压什么、合法动作有几个、
  当前牌面是不是自己打的。

其中"**还剩几轮能走完**"（`estimate_turns`）是最关键的一个：贪心把手牌拆成顺子/连对/炸弹/
三带一等等，数需要几轮出完。它给了网络一个"这一手把牌拆坏了没有"的直接信号。这个函数按
点数签名做了 LRU 缓存，否则训练时每步要重算几十次。

## 试过但没用的东西

这些都实测过、有数据判定无效，**代码已经从仓库移除**（`git log` 里能翻到实现）。
留下结论是因为负结果同样值得记录——尤其能说明这个任务的瓶颈到底在哪。

| 想法 | 结果 | 判定 |
| --- | --- | --- |
| **25× 参数量**（3 层 × 512） | 对 2×rule 45.7% vs 51.3% | 换 PPO 后能追平，但直接对打仍输小模型 |
| **自我对弈**（快照对手池） | 2 万局 −0.9pp；12 万局直接对打 36.1% vs 41.5% | 两种预算、两套口径全负 |
| **原始编码**（点数网格取代手工特征） | 对 2×rule 41.1% vs 53.7% | 12 万局远远落后 |
| **手工 + 原始拼接** | 52.2% vs 53.7% | 多出的 87 维基本冗余，反而稀释信号 |
| **残差连接**（`x + f(x)`，不加参数） | −2.4pp，0/3 种子，t=−5.43 | 稳定有害，加深也更差 |
| **点数轴一维卷积** | PPO 更新慢 32 倍（508ms vs 16ms） | 轴只有 12 格，不值这个代价 |

几点值得展开：

**自我对弈**的失败最反直觉。它的训练曲线是往下走的（42.4% → 38.4%），这不是没学会——
对手就是过去的自己，你变强它也跟着变强，胜率自然被压回 33% 附近，说明军备竞赛在正常运转。
问题是**跑出来的东西没有更强**。比较可信的解释：这个任务已经有一个现成的强参照了。
自我对弈的价值在于没有好对手可用的场合（围棋、星际），而这里我们直接把一个相当像样的
`rule` 递给了模型。换个没有强参照的任务，结论未必一样。

**原始编码**的曲线在 12 万局时**还在往上爬**（33.1% / 35.9% / 38.0%），而手工特征早就平了
（47.9% / 51.2% / 52.2%）。所以严格说"手工特征是天花板"没有被证伪——只是在任何负担得起的
预算内，手工特征都赢。手工特征更像是**小数据量下非常划算的先验**，而不是上限。

**卷积慢**慢的不是计算量，是 PyTorch 在极小张量上的调度开销。PPO 每次更新要前向 5 次，
光这一项就 2.5 秒，训练吞吐从 380 局/秒掉到 27 局/秒，12 万局要一个多小时。

**一条方法论教训**：残差最早是在 2000 局的预算上测的，当时四组全在 33% 基准线附近打转
（模型压根还没开始学），我从 +0.3pp 的差异里读出了"残差是给深网络用的"这种理论支持。
2 万局重测时这个方向**反了**。**在模型还没学起来的时候做 A/B，量到的全是噪声，正负都别信。**

## 三个手写的规则对手

它们既是训练对手，也是衡量模型强弱的标尺：

| 名字 | 打法 |
| --- | --- |
| `random` | 合法动作里均匀随机，纯基准线 |
| `greedy` | 能压就压，永远出最便宜的牌；不留大牌、不管对手还剩几张 |
| `rule` | 会算手牌拆解：优先出拆得最干净的一手、保留炸弹、不用 K/A 去压小牌、对手只剩 ≤2 张时改用大牌压制、能一把走完立刻走 |

`rule` 是个相当像样的对手——它打 `greedy` 有 64.9%，打 `random` 有 78.4%。

## 常用命令

```bash
# 训练：默认只跑 2000 局（约 8 秒），够快速验证一个想法
.venv/bin/python -m paodekuai.train
.venv/bin/python -m paodekuai.train --episodes 120000 --batch 32 --lr 7e-4   # 出正式结果再拉长
.venv/bin/python -m paodekuai.train --algo reinforce           # 切回 REINFORCE 做对照
.venv/bin/python -m paodekuai.train --hidden 512 --layers 3 --save paodekuai/models/big.pt   # 更大的模型
.venv/bin/python -m paodekuai.train --opponent mix          # 每局随机抽两个不同对手，更耐打
.venv/bin/python -m paodekuai.train --help

# 评测：对规则对手的胜率表，--model 可以给多个
.venv/bin/python -m paodekuai.bench --model paodekuai/models/agent.pt --games 1500

# 让两个模型直接对打（每副牌打满 6 种座位排列）
.venv/bin/python -m paodekuai.duel model:paodekuai/models/agent.pt rule greedy --deals 300
.venv/bin/python -m paodekuai.duel model:paodekuai/models/agent.pt rule greedy --deals 300

# 对战 / 观战
.venv/bin/python -m paodekuai.play                          # 你 vs 2 个模型（默认）
.venv/bin/python -m paodekuai.play --hint                   # 每步先看模型建议再自己决定
.venv/bin/python -m paodekuai.play --opponent rule          # 换成规则机器人
.venv/bin/python -m paodekuai.play --watch                  # 观战，回车逐步推进
```

## 测试

```bash
.venv/bin/python -m unittest discover -s paodekuai/tests -t .
```

149 个测试，约 3 秒。除了常规的牌型和引擎规则，有五个值得一提：

- **牌型往返一致性**：随机发几百手牌，枚举出的每一个合法动作都要能被 `classify()`
  反向识别成同样的牌型、点数和连长——生成器和识别器互相验证。
- **规则对手强弱梯度**：断言 `rule > greedy > random`，并且同类打同类必须落在 33.3% 附近。
  这条测试挂了，说明评测口径出了问题，模型胜率也就没有意义了。
- **变长动作集的掩码**：补齐用的填充位概率必须恒为 0，且批量打分要和逐个打分数值一致。
  掩码漏一点，梯度就全错，而且训练照样能跑完、只是学不出东西——这种 bug 最难发现。
- **自我对弈的快照必须真冻住**：存进对手池的快照，后续训练不能改动它的权重。快照要是跟着
  主模型一起变，"跟过去的自己打"就退化成"跟当前的自己打"，自我对弈的意义就没了。
- **打分必须逐个候选独立**：同一批候选一起算、一个一个算、后面补一堆假零行再算，三种方式
  得到的分数必须完全相同。这条钉住了"不能用 BatchNorm"（见下），换成 BatchNorm 会直接挂。

## 可以继续做的事

- **继续补特征**："带牌点数"那次实验（见上）说明补信息是有效的方向。还缺的比如"这手牌之后
  自己手上最大的牌是什么"、"暗牌里还剩几个炸弹"。更彻底的做法是换成原始牌面 + 编码器让网络
  自学特征，那样大模型的容量才可能真正兑现。
- **给 `raw` 编码更大的数据量**：它在 12 万局时还在往上爬（见上），只是爬得慢。
  真要验证"学出来的表示能不能超过手工特征"，得上百万局级别的预算，可能还要配合
  向量化环境（现在每局都是纯 Python 单线程跑的）。
- **继续补手工特征**：目前唯一稳定有效的方向。还缺的比如"这手出完之后自己最大的牌是什么"、
  "暗牌里还剩几个炸弹"、"上家过牌说明他大概率没有什么"。
- **补全信息利用**：现在只用了公开信息，可以加对手手牌的概率推断。
- **换变体**：连对最少几对、飞机怎么带、要不要保留 2 和王，都在 `combos.py` 顶部集中定义。
